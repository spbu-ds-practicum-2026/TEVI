# Техническое решение проекта «Notes hub»

## Введение
- **Цель проекта:**  
  разработать прототип распределённой системы для коллективного хранения конспектов, выбора наиболее актуального среди них и их резервного копирования.  

- **Основания для разработки:**  
  учебный проект по курсу «Основы распределённых вычислений» в СПбГУ

## Глоссарий
| Термин                                          | Определение                                                                                                                                    |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Узел                                            | Серверный процесс, хранящий реплику данных и обрабатывающий клиентские запросы                                                                 |
| Конспект                                        | Файл расширения `pdf` или `md`, относящийся к определённому предмету и номеру лекции                                                           |
| Хранилище                                       | Директория на узле, в которой хранятся все конспекты                                                                                           |
| Пользователь                                    | Зарегистрированный в системе клиент                                                                                                            |
| Реплика                                         | Копия данных, созданная для поддержки отказоустойчивости системы                                                                               |
| Репликация                                      | Процесс создания и поддержания реплик на нескольких узлах                                                                                      |
| Конфликт                                        | Ситуация, в которой два или более конспекта, относящиеся к одному и тому же предмету и номеру лекции, претендуют на место наиболее актуального |
| Алгоритм разрешения конфликтов                  | Алгоритм, рассматривающий все файлы, находящиеся в конфликте, и выбирающий наиболее актуальный среди них по заданным правилам                  |
| Конечная согласованность (Eventual consistency) | Свойство системы, при котором все узлы приходят к общему состоянию через некоторое время без внесения изменений в систему                      |

---

## Функциональные требования
Система должна предоставлять следующие функции:
1. Предложение добавления конспекта по выбранному предмету и номеру лекции
2. Получение актуального конспекта по выбранному предмету и номеру лекции

---

## Нефункциональные требования
Система должна поддерживать следующие свойства:
- Поддержка горизонтальной масштабируемости
- Доступность: 99,9%
- Отказоустойчивость
- Конечная согласованность

---

## Пользовательские сценарии
1. Предложение добавления конспекта
	- Пользователь выбирает желаемый файл для предложения по выбранному предмету и номеру лекции в клиентском приложении
	- Клиентское приложение отправляет запрос на рассмотрение обновления в систему
	- Система выполняет сравнение с текущим вариантом конспекта и в случае, если предложенный оказывается актуальнее, заменяет старый или отсутствующий конспект на предложенный
	- Пользователь получает обратную связь от системы о принятом решении
2. Получение актуального конспекта
	- Пользователь выбирает желаемый предмет и номер лекции в клиентском приложении
	- Клиентское приложение отправляет запрос на чтение в систему
	- Система выбирает наиболее актуальный из доступных конспект и возвращает пользователю файл с ним
	- Пользователь получает файл с конспектом
